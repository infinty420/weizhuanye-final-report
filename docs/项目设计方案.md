## 0. 文档定位：从"发现"到"升级"

发现报告给出的是**待验证需求假设**（REQ-1~6），业务挖掘报告把机会/基线/章程做了第一轮自评（平均 68.7 分）。本方案做三件事：

1. **接住原型**：把 `qingshan-demo` 已实现的能力映射到 REQ，避免重复造轮子。
2. **修正扣分项**：落实挖掘报告反馈——事实编号改为真实 `f*` 编号、叶书定位为"反馈受理"而非"验收签字"、唐映秋为"筹备项目专员"而非"项目经理"、基线区分"访谈已给出/待验证"、补齐返工/错误/完成口径冲突指标。
3. **给出可落地的分阶段路线**：历史回放 → 小范围并行 → 数据治理 → 规模化闭环。

## 1. 升级背景与问题诊断（现状瓶颈）

依据 `现状业务流程图.png` 与发现报告证据：

- **主流程**（f01/f20）：选址确认 → 装修 → 设备安装 → 商品上架 → 人员培训 → 开业验收。链顺但各节点等待/处理耗时尚未量出（f01），店长看不到"哪项延期卡开门"。
- **跨群依赖不可见**（f10）：装修/设备/商品分属三个独立群，进度各自为政；任务散落在三套互不相通系统（项目管理表、供应商平台、设备台账，f30）。
- **典型事故**（f11）：冷柜安装完成、但电力增容未验收 → 生鲜到货无法入库，直接冲击开业节点。原型 `GRAPH` 已将此关键路径（电力增容→冷柜→生鲜入库）建模为 `crit/ gate` 边。
- **数据缺陷**（f31/f33）：照片仅记上传日期、无验收日期；负责人缺统一身份；主编号/事件时间/版本待校验；歧义记录须进人工修复队列、不进自动推荐。
- **根因判断**（f00/f10）：延期率 32%、漏项 11 项/店，瓶颈在**跨群依赖可见性**而非单点执行——这正是 AI 首期只读试点（REQ-1）的切入口。

## 2. 升级愿景与业务结果目标

依据 `数智化转型后业务流程图.png` 与发现报告：AI 依赖识别与筹备提醒引擎 = 只读试点、不代签工程验收/付款（f05/f52）。

**业务结果目标（验收须挂到这些，而非功能）**（f00/f02/f42）：

| 指标 | 现状基线 | 目标 | 性质 |
|---|---|---|---|
| 新店延期率 | 32% | ≤15% | 访谈已给出，分母/归口待验证 |
| 筹备任务漏项 | 11 项/店 | <3 项/店 | 访谈已给出，判定依赖验收日期 |
| 关键依赖识别完整率 | — | ≥95% | 分母待核实（§6） |
| 安全验收漏项 | — | 零漏项 | 消防/用电/食品，傅景判定（f40/f42） |
| 店长进度汇总工时 | 6h/周 | 大幅下降 | 访谈已给出，需按周逐笔采集 |

> 注意：店长常提的"看板/自动提醒/手机推送"是**功能手段**，验收必须挂到上表业务结果（挖掘报告任务1 反馈）。

## 3. 升级范围与边界（"四不做"）

来自 REQ-3/4/6 与 f05/f22/f32/f40/f41/f45：

1. **只读**：三系统只读接入，不自动签署供应商验收或付款（f32）；写回作为待验证假设单独评估。
2. **不代签**：工程验收"代签"属不可逆风险，系统绝不代签，AI 仅提醒（f05/f52）；唐映秋可整理校核发起复核，不能代签（f22）。
3. **人工兜底**：资料缺依据/版本冲突/关键系统不可用/电力增容未验收 → 转人工，须标注触发原因、接手人、确认时间（f44/f15）。
4. **留痕与红线**：每次建议保留业务编号/资料版本/事实引用/建议结果/人工改动/签核人（f45）；消防/用电/食品验收不可跳过，违规项不得标记已完成（f40）。

## 4. 总体架构蓝图（映射原型现状）

`数智化转型后业务流程图.png` 的六个输出节点，对应原型 `qingshan-demo` 现状如下：

| 架构层 | 蓝图能力 | 原型现状（已实现/未实现） |
|---|---|---|
| 输入层 | 三系统只读拉取 + 统一业务编号/版本口径 | ✅ `adapters.js`：三系统 JSON 抽取 + `门店-群-序号` 统一主键 |
| 数据底座 | 跨系统对齐 + 任务依赖图谱 | ✅ `GRAPH`（电力增容→冷柜→生鲜关键路径已建模）；⚠️ 真实 API 接入未做（现读本地 JSON） |
| AI 引擎 | 依赖识别 + 筹备提醒 | ⚠️ 当前为规则图谱 + 人工标注回放，模型判定未接入 |
| 实时筹备看板 | 店长一眼看"哪项影响开门" | ✅ 前端 KPI 卡 + 门店风险标签 + 依赖图谱着色 |
| 智能提醒/超时预警 | 按节点派发 + 超时 | ⚠️ 仅"事故模拟"触发，常态化超时预警未做 |
| 安全硬约束闸门 | 消防/用电/食品不可跳过 | ✅ `simulateAccident` 电力增容未验→生鲜 `block`；`recheckFresh` 人工签核解除 |
| 异常转人工兜底 | 触发原因/接手人/确认时间 | ⚠️ 现仅 `ack/signoff`，分派规则与接手人对应未建模（f25/f44） |
| 审计留痕 | 编号/版本/事实/签核人 | ✅ `pushAudit` 已记录来源与签核人；⚠️ 90 天留存复核删除节点未做（f43） |

**结论**：原型已把"数据对齐 + 依赖可见 + 安全闸门 + 审计"骨架跑通，升级重点在**数据治理、常态化提醒、兜底分派、鉴权与留存**四块补强，而非重建。

## 5. 分阶段实施路线（Wave 制）

遵循发现报告"先历史回放、再小范围并行、不直接替换现有流程"（f05）。

| 阶段 | 目标 | 对应 REQ | 核心交付 | 负责人 | 验收/停止条件 |
|---|---|---|---|---|---|
| **W0 回放验证**（只读） | 用 1 家历史店资料回放，人工标注关键依赖，形成依赖项清单与 95% 分母口径 | REQ-1, REQ-2 | 依赖项清单、统一编号字段规则、人工修复队列样例 | 唐映秋（标注）+ 秦芮（口径）+ 林亦舟（现场核对） | 顾明岚确认清单与试点范围；分母未定前不进入 W1 |
| **W1 并行试点**（3 家新店） | 只读提醒 + 看板落地，安全闸门拦截演练 | REQ-1, REQ-3, REQ-4 | 3 店实时看板、超时预警、闸门拦截演练、异常转人工标注 | 林亦舟（一线）+ 傅景（安全签核）+ 唐映秋（分派） | 关键依赖识别完整率≥95%、安全验收零漏项（f02/f42）；触及停止条件即暂停复盘 |
| **W2 数据治理与口径固化** | 照片验收日期+统一身份、修复队列、快照降级、完成双口径 | REQ-2, REQ-5, REQ-6 | 字段对齐试算、人工修复队列、快照"暂未更新"+去重补齐、供应商/运营完成时间分别记录 | 秦芮（系统承载）+ 唐映秋（资料责任）+ 叶书（完成口径） | 歧义比例统计达标；"完成"定义冲突写入口径卡（f50/f53） |
| **W3 规模化与反馈闭环** | 周度误判收集、规则版本迭代、审计留存 | REQ-4, REQ-6 | 每周误判/未解问题表、规则版本更新机制、90 天留存复核 | 叶书（受理）+ 顾明岚（改进负责人确认）+ 傅景（留存复核） | 先复测 W1 双指标再更新规则版本（f55/f43） |

每阶段均嵌入**停止条件**（f42）：安全验收漏项 → 闸门拦截禁上线；试点异常 → 暂停复盘；数据访问未授权 → 停止拉取；审批缺失/越权 → 退回不标记完成。

**代价假设**（均案例估计，须访谈确认计费依据，f03）：店长工时 50 元/h，年化节约 ≈ 12店×6h×4.3周×50 ≈ 15.5 万元；收益须扣维护与人工复核成本，不得把节省工时当现金回款。

**完成口径冲突**（f50/f53）：供应商按安装结束、运营按可营业，须分别记录各岗完成时间，固定分母/排除规则/统计周期，避免同一业务拆成多次"成功"抬高比例。

## 8. 风险闸门与兜底机制（P0）

- **安全硬约束前置**（REQ-3）：消防/用电/食品验收不可跳过，违规项不得标记已完成（f40）；原型 `simulateAccident` 已实现"电力增容未验→生鲜 block"拦截，需傅景固化不可跳过项清单 + 每项审批人（f42）。
- **兜底分类**（REQ-4）：资料缺依据/版本冲突/关键系统不可用/电力增容未验收 → 转人工，标注触发原因、接手人、确认时间（f44）；异常先由唐映秋分派、超时升级顾明岚（f25）。
- **快照降级**（f34/f35）：接口中断用带时间戳只读快照并显示"暂未更新"；重连按业务编号去重补齐；超一更新周期标待刷新，不作实时承诺。
- **审计**（f45/f43）：保留业务编号/版本/事实引用/建议结果/人工改动/签核人，可重建处理链；评价记录暂留 90 天、期满由傅景复核删除或归档，真实期限按组织规则另定；不记录口令与不必要个人信息。

## 10. 待核实阻塞项清单（章程签字前必须闭环）

汇总自发现报告 §"建议继续追问" 与挖掘报告待补项，按对"有条件立项"的阻塞程度排序：

1. **P0 阻塞**：95% 完整率分母与核算责任人；不可跳过验收项清单 + 每项审批人；停止后复盘责任人（f42）。→ 傅景/顾明岚 本周固化。
2. **P0 阻塞**：三系统只读接口可用性 + 读接口能否稳定返回业务编号/版本字段（f30/f32）。→ 秦芮 验证。
3. **P1**：完成"单"的定义与统计周期、反馈受理入口与首次回应时限（f51/f54）。→ 叶书/顾明岚。
4. **P1**：照片验收日期/负责人统一身份归属、人工修复责任人与时限（f31/f33）。→ 唐映秋/秦芮。
